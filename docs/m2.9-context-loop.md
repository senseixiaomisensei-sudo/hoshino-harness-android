# M2.9 WP9-B：上下文与循环质量

本工作包只用原版 dsh 0.2.2-alpha.2（精确锁定、未修改）已有的扩展点和 Cordis 插件实现，不 fork dsh。部分规则移植自 Mika（Apache-2.0，见 `THIRD_PARTY_NOTICES.md` 的 WP9-B 段）。

## 组成

| 位置 | 内容 |
|---|---|
| 原版 dsh 包（`rootfs/runtime-seeds.json` 追加，`node-host/src/main.ts` 装载） | `compaction-tool-result-pruner`、`compaction-image-offload`、`command-compact`（/compact）、`repeat-tool-reminder`（阈值 3/5/8，排除 todo_write/ask_user）、`tool-call-timeout-policy`、`time-context`（时区来自 App 启动参数 `timeZone`，每 5 分钟刷新） |
| `plugins/hoshino-context/compaction.js` | 作为 `compaction` 服务替换原版引擎：继承原版 `BasicCompactionEngine`，只覆盖其公开的 `summarize()`。被折叠区间里用户的每一句原话逐字附在摘要后（CX2）；`strategy: rules` 或模型摘要失败/不变小时写确定性的无模型检查点；摘要模型优先用 `routing.json` 的 `compact` 路由 |
| `plugins/hoshino-context` | CX1 缓存账本（命中率、前缀变动原因）、CX2 非标准措辞的超长报错→压缩后重试、CX5 外部内容 `<untrusted>` 包裹、`/mobile/context` 控制端点 |
| `plugins/hoshino-turn-policy` | RT10 意图拦截（讨论类问题不执行写工具，先于审批）、RT11 回答前提醒（空回复、语言不符、未回读，各一次）、RT12 连续失败阶梯与安全停止、SB4 沙盒时间预算、RT16 临时故障（429/5xx/网络）同路由重试与可读失败原因、CX6 步数提示 |
| `plugins/hoshino-outcome` | RT9 `end_not_done` 工具与回合结局判定（规则优先，只有做了事的回合才问轻量模型），结局写入原版会话日志 `plugin:hoshino/outcome`；RT17 轻量依据检查 |
| App | `core/ContextControl.kt`：手动压缩（`HarnessClient.compact`）、内核 `context-notice` 回调转成会话内提示；`KernelLauncher` 传设备时区 |

## 设置

`<selfHome>/config/context.json`，缺失或损坏时用默认值，不会阻止内核启动。默认值见 `plugins/hoshino-context/state.ts` 的 `DEFAULT_SETTINGS`：

- `compaction.strategy`：`auto`（模型摘要，失败回退无模型）/ `rules`（从不调用模型）；`thresholdRatio` 0.3–0.95，默认 0.7
- `guard`：`failureWarn` 2、`failureStop` 8、`sandboxLoopWarn` 3、`sandboxLoopStop` 5、`sandboxBudgetMs` 30 分钟
- `retry`：最多 3 次、累计等待 ≤30 s
- `intent` / `turnPolicy` / `outcome` / `untrusted`：各项开关

## `/mobile/context`

与 `/mobile/control` 相同的 cookie 准入（未认证 403）。`POST {action}`：

- `compact` + `sessionId`：执行原版 `/compact` 命令
- `status` + `sessionId`：缓存账本、压缩计数、预算、最近结局
- `settings`（可带 `settings` 局部更新）、`defaults`

内核→App 的提示走桥接回调 `context-notice`，`kind` 为 `compaction | guard | failure | outcome`，App 只认这四种，文本截断到 1200 字。

## 排查记录

- 内核测试「就绪前 120 秒超时」：不是卡死。冷启动时依赖在 JuiceFS 上，基线（不装 WP9-B）仅模块加载就约 100 s、113 s 就绪；WP9-B 多 7 个原版包 + 3 个插件后超过 120 s。缓存热后完整组合 18 s 就绪。测试就绪上限改为 300 s。另：只跑 `tsc` 不跑 `tools/generate-self.mjs` 时缺 `dist/self-input.json`，延迟初始化的自述文档写入失败（`main.ts` 吞掉错误只打一行 deferred），基线同样如此，属构建步骤不全，`npm run build` 即可
- 修复的真实缺陷：
  - dsh 把「完成但无内容」的回复报为 `EMPTY_RESPONSE` 请求错误，`agent/turn-stopping` 根本看不到空回复 → 在 `agent/request-error` 里追加一次提醒到 surface 后重试（第二次仍空则按原错误结束）
  - pi-ai 路由（OpenAI 兼容 / Anthropic）的失败没有 `status`，状态码在消息前缀（`503: {...}`），代码是 `SERVER/AUTH/RATE_LIMIT/TRANSPORT/TIMEOUT` → 原分类全落到 unknown，503 不重试、401 不提示。现按前缀和 dsh 规范代码分类
  - 安全停止的结局：停止说明是追加的 `hoshino-guard` 提示而非工具结果，结局判定读不到，被模型判成「办成」。现从本回合事件读取，不再依赖跨回合残留的会话账本
- 测试夹具修正：超长场景改为「直到本回合历史真的变短才停止报错」（之前历史里已有旧摘要，夹具从不报错，断言测不到东西）；CX1 前缀稳定性在内核延迟初始化（subagent/goal/schedule 工具约在就绪 1 s 后注册）完成后再测
