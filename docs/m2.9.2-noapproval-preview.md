# m2.9.2：彻底无审批 + 虚拟屏预览（缩放 / 错位 / 手势 / 横竖屏 / 自由操作）

来源：用户在小米 15S Pro 上装 m2.9 后的反馈，以及两条追加要求。版本号不变（随 m2.9.x 发布）。以下根因均为代码推断，**未在真机复现**；真机验收清单见文末。

## 1. 无审批 = 彻底无审批

### 审批入口清单（grep `approve|approval|confirm|ask_user|needsUser|handoff|risk`）
| 入口 | 位置 | 无审批下 |
|---|---|---|
| 工具审批（write/edit/bash/web_*/system_shell 高危档/share_*/clipboard_*/app_screenshot/deliver_file/self_*/plugin_install…） | `plugins/android-policy` → `androidBridge.call('approve')` → `hoshino-m2/approval.ts` | 自动放行，审计 `approver=auto-none` |
| 手机不可逆步骤 `phone_irreversible` | `plugins/android-phone/steps.ts` → 同一口子 | 自动放行；m2.9.2 起 Android 侧不再停下等授权 |
| 付款 / 密码 / 验证码 / 人机验证（原「交给用户」） | `StepRunner.handsOnly` / 密码框 / `IrreversibleDetector pay` / 步骤后 `needs_user` | **不再停**，逐条审计 `no-approval pass reason=… pkg=…`（只记原因与包名） |
| 子 Agent（spawn / fork_agent）里的以上全部 | 子会话自己的 sessionId | **m2.9.2 根因修复**：继承父会话的审批档 |
| Android 审批卡 / 通知 / 悬浮球审批按钮 | `DshHarnessClient` `approve` 回调 → `ApprovalRequested` | 兜底：本会话已知是无审批时直接放行，不发事件 |
| 完全访问风险确认 | `ChatScreen` `FullAccessRiskDialog` | 无审批会话里不再弹（系统授权仍需就绪） |
| 开无审批的风险说明 | `NoApprovalRiskDialog` | 只弹一次，确认即永久记住（去掉了「不再提示」勾选） |
| 系统级确认（APK 安装、运行时权限、Shizuku 授权） | Android 系统 | 无法绕过（系统弹窗，不是 Hoshino 的审批） |

仍然生效（不是审批）：权限档（只读 / 工作区 / 完全访问）、用户自己写的 deny 规则、`system_shell` 主屏守卫（防止操作用户主屏，路由正确性）。`ask_user` 是模型提问，不是审批，未改。

### 根因
1. **子 Agent 不继承无审批**：`approval()` 按 `action.sessionId` 取 `scopes.sessions[id]`。子 Agent 在自己的子会话里执行（`exec.agent.id` = 子会话 id），子会话从来没有单独的审批档，于是落回默认 `manual`，在「无审批」会话里照样弹卡。修复：`approvalSessionFor` 沿会话头 `parentSession`（dsh-subagent `childSessionMeta` 写入）向上找最近的单独设置；`approval-state` 的 `effective` 同样按链计算；审计里带 `inheritedFrom`。
2. **手机侧硬拦截**：付款 / 密码 / 验证码 / 人机验证在 Android 执行入口任何档位都停下交给用户（M2.8 决定）。按用户要求，无审批下改为照常执行：内核把 `no_approval: true` 随 `phone steps` 下发（由 `mobileM2.noApproval(sessionId)` 判定，含子 Agent 继承），`StepRunner` 拿到 `NoApprovalBypass` 后不再停、不再要一次性授权，每条放行写审计；无审批会话额外注入一句提示词，告诉模型不要自己去 handoff。
3. **重复弹风险说明**：未勾「不再提示」时每次切换都会再弹。改为确认一次即记住。

### 测试
- `node-host/test/m292-no-approval.test.mjs`：23 类审批动作在无审批会话里 0 个待审批项且全部审计；子 / 孙 Agent 继承；默认档为无审批时同样；所有插件的 `'approve'` 调用都经过被包装的 `androidBridge.call`（静态检查，防绕过）；`runSteps` 无审批时带 `no_approval`，付款停下也走审计口子。
- `app/src/test/.../NoApprovalStepsTest.kt`：不可逆 / 付款 / 支付密码键盘 / 密码框 / 验证码 / 滑块在无审批下全部执行且有审计、无内容；步骤后遇到要人处理的页面不再中断；非无审批行为不变；Android 兜底 `autoAnswer`、完全访问不弹、风险说明一次。

## 2. 预览不能放大缩小

### 根因
面板高度上限是 `屏高 − 300 dp`（给进度行 / 按钮 / 插话框留的固定空间），宽度按纵横比反推。在 6.7" 竖屏上预览宽只能在约 120–265 dp 之间变化，而卡片最小宽 280 dp，窗口宽度几乎不变——拖角 / 捏合确实在改，但看起来「不能缩放」。另外角标只有 32 dp、半透明黑底，在黑色画面上几乎看不见。LayoutParams 本身是实时更新的，TextureView 不吃触摸，接管与否不影响。

### 修复
- 进度、按钮、插话等收进「控制面板」（默认折叠，单击打开）；上限改为 `屏幕 − 标题栏 − 边距`（`PreviewGeometry.limitsFor`），最小 64 dp（约等于悬浮球），竖屏可拉到接近全屏宽 / 高，横屏按宽度限制。
- 右下角手柄：44 dp 触摸区、28 dp 蓝底白边可见标记，`requestDisallowInterceptTouchEvent`；双指捏合在预览上始终可用（接管 / 非接管）。
- 每次变化直接 `updateViewLayout`（卡片宽 = 预览宽 + 内边距，不再有 280 dp 下限）；尺寸按方向分别记住（`previewW_portrait` / `previewW_landscape`，旧 `previewW` 迁移为竖屏）；「缩放复位」。

## 3. 画面「稍微错位」

### 根因
显示与触摸用的是三套各自取整的变换：后台屏 → 360 宽预览 Bitmap（高度截断，纵横比与后台屏不完全一致）→ `ImageView.FIT_CENTER` 自己算的矩阵；触摸走 `fitViewport` 的截断整数视口 + 截断映射。三者在 letterbox 偏移和缩放上各差 0.5–2 px，放大后可见。另一个潜在问题：`ImageReader` 行有 padding（`rowStride > width × 4`）时，代码靠把帧 Bitmap 建成 rowStride 宽来规避；末行不带 padding 的驱动上缓冲区比 Bitmap 小，`copyPixelsFromBuffer` 会抛异常，任何直接用整幅帧的地方都会横向错位并在右侧留黑边。

### 修复
- `PreviewTransform`：唯一的后台屏 ↔ 预览变换（四舍五入的 fit-center 视口）。Bitmap 回退改 `ScaleType.MATRIX`，矩阵来自 `bitmapMatrix()`（每轴单独缩放，吸收 360×801.3→801 的取整）；GPU 零拷贝的 GL 视口用同一个 `fitViewport`；触摸用同一个 `toDisplay`。像素中心往返误差 ≤ 1 px（单测覆盖竖屏、横屏、letterbox、pillarbox、极小 / 极大预览）。
- `StridedFrame.pack`：先把每行裁到 `width`（含末行短缓冲、非常规 pixelStride），帧 Bitmap 恰好是后台屏尺寸。

## 4. 手势（追加）
`TapClassifier`（单测）：只作用于悬浮球、标题栏和面板边框。
- 单击 = 控制面板（停止、接管 / 交还、帧率 ±5、竖屏 / 横屏 / 跟随 App、缩放复位、发此刻屏幕）；单击在 `ViewConfiguration.getDoubleTapTimeout()` 过后才触发，双击绝不同时触发单击。
- 双击 = 最小化为悬浮球并停止渲染（自动接管先交还；「接管」按钮锁定的接管拒绝收起）。
- 拖动超过 touch slop 即为拖动，不触发点击；按住超过 500 ms 不算点击。原「双击小球发此刻屏幕」移到控制面板按钮。
- 预览区内的触摸一律注入后台屏，不参与这两种手势。

## 5. 横屏 / 竖屏 + 自由操作（追加）
- AIDL 新增 `resizeDisplay(displayId, surface, w, h, dpi) = 50`（`VirtualDisplay.setSurface(null) → resize → setSurface(new)`，返回值从不为 0）。`AgentDisplay.resize` 换新尺寸的 ImageReader，宽高互换、dpi 不变，`shape` StateFlow 通知预览；零拷贝 relay 按旧尺寸建，切换后改用 Bitmap 预览。**旧版助手进程没有这个方法（返回 0）**：不切换，并提示到「设置手机操作」重新连接助手。
- 控制面板「竖屏 / 横屏 / 跟随 App」（`phone_capsule.orientation`，默认跟随）。跟随 App 每 800 ms 看前台 Activity 的 manifest `screenOrientation` 与无障碍窗口边界（虚拟屏不旋转，运行时 `setRequestedOrientation` 的 App 会被 letterbox 成另一形状的窗口），连续两次一致才切（`OrientationFollower`），步骤执行中不切（`tryLock`）。
- 预览随之换纵横比，触摸映射用同一 `PreviewTransform`；`phone_status` 返回 `agent_display {orientation, width, height, mode}`，模型坐标 0..999 始终按当前方向。
- 自由操作（`AutoTakeoverModel`，单测）：预览上第一次触摸即自动接管、AI 暂停；松手 4 秒无操作自动交还（AI 拿到一句「你做了什么」）；打字 / 按键 / 捏合算活动；「接管」= 锁定，直到「交还」。

## 真机验收（小米 15S Pro，未做）
1. 无审批会话：写文件、rm、system_shell reboot 类、分享、截图、子 Agent 里写文件、微信发送、支付宝付款页、密码框、验证码页——全程无卡片 / 通知 / 悬浮球按钮；`audit/approvals.jsonl` 与手机审计各有记录。
2. 手动审批会话行为不变；第一次开无审批只弹一次说明。
3. 预览从约悬浮球大小拉到接近全屏；接管与否都能拖角 / 捏合；重开面板尺寸保留。
4. 放大到最大时点按位置与画面一致（边角 ≤1 px 级）；右侧无黑边。
5. 单击 / 双击 / 拖动悬浮球与标题栏：单击稍有延迟后出控制面板，双击收回，拖动不误触。
6. 横屏 / 竖屏 / 跟随：B 站或抖音视频全屏后后台屏自动转横，退出后回竖；横屏下点按准确；`phone_status` 显示方向。若提示需新版助手，先重连助手。
7. 自由操作：不点接管直接点画面 → AI 暂停；停手 4 秒后 AI 继续。
