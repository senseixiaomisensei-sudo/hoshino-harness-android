# M2.7 · 流畅度、内存、交付文件卡归位、审批折叠

分支 `feat/m2.7-perf-files`。只改 Android UI/桥接层与 `plugins/hoshino-m2` 的 `deliver_file` 参数；dsh 版本与源码不动，默认审批策略不变。

## 1. 流畅度与内存

| 问题 | 之前 | 现在 |
|---|---|---|
| 流式文本拼接 | `text + delta`，每个 token 复制整段，O(n²) | `StreamText` 追加式 rope：所有快照共享只追加缓冲，`append` O(delta)，`equals` 同缓冲 O(1)；被重复追加的旧快照（CAS 重试）自动分叉，语义不变 |
| `DshHarnessClient.Live` 累积 | `String +=` | `StringBuilder` |
| SessionStore 每 32ms 提交 | 复制整个 `items` 列表 | 状态按轮次分组（`TurnItems`，身份相等）：一次提交只复制最后一组，其余轮次保持同一实例 |
| MessageList | 每次更新 `presentTurns(全部条目).asReversed()`，每轮是一个大 item | `TurnPresenter` 按 `TurnItems` 实例缓存，只重算当前轮；当前轮里没变的行沿用旧实例；每轮拆成多行（用户/过程/动作卡/回答/文件卡/用量），稳定 `key` + `contentType` |
| Compose 稳定性 | `ChatItem` 含 `List` 字段，Compose 视为不稳定，从不跳过 | `ChatItem`、`TurnPresentation`、`ChatRow`、`MdBlock`、`DeliveredFile`、`StreamText` 标 `@Immutable`；`MessageActions` 在 `ChatScreen` 中 `remember`；过程组配置包成不可变的 `ProcessDisplay` |
| ChatScreen 本体 | 直接读取整个 `SessionState`，流式每帧整屏（顶栏、输入框）重组 | 只持有 `State`，`running/queued/contextUsage` 用 `derivedStateOf` 取出；消息列表在独立作用域 `SessionMessages` 中读取 |
| Markdown | 每帧整段重解析 | `IncrementalMarkdown`：代码块之外的空行是安全边界，边界之前的块只解析一次并缓存，每帧只重解析最后一个块；每块是独立子组合，未变的块跳过重组 |
| 过程组计时 | 整卡每秒重组 | `ElapsedLabel` 局部计时，只重组标题里的时长文字；思考块计时同理 |
| 过程组长度判断 | 每次重组 `plainText()`（整段 Markdown 解析） | 直接用长度，展示文本 `remember` |
| 轨迹 | 每轮存系统提示、完整工具输出、整段回答 | 只存摘要（≤2000 字符 + 总长度说明），最多 1000 条 |
| 工具/终端输出 | 全量常驻内存 | 只保留尾部 64 KiB（`OutputTail`），参数只保留开头 64 KiB；卡片显示总长度，「查看完整输出」按需从 dsh 会话 JSONL 读取（`HarnessClient.fullToolOutput`），写入可分享的缓存文件，分块懒渲染 |
| 会话状态 | `ConcurrentHashMap` 无淘汰 | LRU，只保留最近 4 个会话；运行中、有排队消息、正在被界面订阅、刚访问的会话不淘汰。被淘汰的会话 `releaseSession`（取消订阅、忘掉去重序号），切回时 `retainSession`/`activateSession` 重新订阅，内核发完整快照重放恢复。不支持重放的客户端（Fake）不淘汰 |
| 交付文件预览 | 主线程解码，图片固定 `inSampleSize=2`，PDF 两倍页面尺寸 | 全部在 `Dispatchers.IO`；图片先读边界再按显示尺寸做 2 的幂下采样；PDF 按屏幕宽度缩放渲染；ZIP/DOCX/文本读取也在 IO |

与 Mika（`ui/ChatScreen.kt`、`ChatViewModel.kt`）对比：Mika 同样把每轮拆成多个带 key 的 LazyColumn item，活动更新时只替换进行中的那一轮（`exchanges.toMutableList()` 后改 `liveIndex`）；但 item 没有 `contentType`，且没有按轮次实例缓存展示结果、追加式文本、增量 Markdown 与局部计时。本分支补上了这些。

## 2. 交付文件卡归位

- `plugins/hoshino-m2`：`deliver_file` 把 dsh 的 `ToolExecution.rootCallId`（= 会话日志 `tool/call` 的 `callId`）作为 `callId` 传给原生桥（`deliver.ts`）。
- `DshHarnessClient` 记录每个会话正在运行的轮次（`turn/start` 事件 id，形如 `e:<seq>`，来自持久化序号，重放后稳定）以及每次工具调用所在轮次；`M2Runtime.file.deliver` 据此写入 `DeliveredFile.turnId`、`deliveredAt`、`callId`。
- `hoshino-deliveries.json` 新增上述三个字段；旧记录（只有 5 个字段）照常读取，`deliveredAt` 退回到文件修改时间（`DeliveredFileCodec`）。
- 新事件 `HarnessEvent.FileDelivered`：新交付立即发出；会话快照重放后、启动缓存重放后，把该会话的历史交付重新发出。`SessionState.deliveries` 持有本会话文件，`turnMarks` 记录每个 dsh 轮次落在哪个展示分组及开始时间。
- 归属规则（`TurnPresenter.placeDeliveries`）：有 `turnId` → 该轮；否则按 `deliveredAt` 归到开始时间不晚于它的最近一轮（早于所有轮次归第一轮）；都没有 → 最后一轮。
- 删除列表底部常驻的 `delivered-files` item；文件卡渲染在所属轮次的最终回答下面、用量脚注之前。预览/保存/分享·打开保留。

## 3. 审批折叠（UI）

- 设置 → 外观 → 对话 →「审批后折叠」，默认开，存放在现有的 `hoshino-ui` SharedPreferences（随备份/恢复）。
- 开：已处理的审批卡从对话中消失，进入该轮过程组，展开后只显示一行小字，如「已允许 · write report.md」「已拒绝 · bash」；标题附「审批 N」。未处理的审批照常显示为卡片，过程组标题显示「等待审批」。
- 关：旧样式，卡片留在对话里并显示处理结果。
- 未改 `plugins/hoshino-m2/config.ts`、`approval.ts`、输入框模式切换与删除会话（另一分支负责）。
