# m2.10：关于页版本号与检查更新、skill_save 加固

对应差距报告 U2、T9（Mika v0.1.18 a9f7569/28e90b9、v0.1.27 5b97ea4）。

## 关于页

- 版本号读 `PackageManager.getPackageInfo`（真正装着的 versionName / versionCode），读不到退回 `BuildConfig`；设置首页「关于」右侧同样改为真实版本（原来写死 `0.1.0 (1)` / `v0.1.0`）。
- 「检查更新」：只请求本仓库 `GET /repos/senseixiaomisensei-sudo/hoshino-harness-android/releases?per_page=30`（不带 token，含预发布，跳过草稿）。
  - 版本比较只看 versionCode：取 Release 说明里第一处 `versionCode N`；没写的 Release 跳过。
  - 资产只选名字以 `-arm64-v8a.apk` 结尾且不含 `debug`/`x86` 的那一个（不会选 `x86_64-debug`）。
- 下载：进程级协程 + HttpURLConnection，写到 `filesDir/hoshino/updates/about/`，下载前清空目录；超过 Release 附件大小立即中止。
- 安装前核对（`ApkIntegrity`，全部失败即删文件并说明原因）：
  1. 下载地址是本仓库 `https://github.com/<repo>/releases/download/...-arm64-v8a.apk`；
  2. 文件大小 == Release 附件 `size`；附件带 `digest`（sha256）时必须一致；
  3. 安装包包名 == `dev.hoshino.app`（且当前进程也是它）；
  4. 安装包 versionCode > 当前已装 versionCode；
  5. 签名证书集合（各证书 SHA-256）与**当前已装包现读**的一致（轮换签名时已装证书须在新包签名历史里）。不写死指纹；当前发布证书为 `e20b0b97…8fd1`。
- 通过后整份写入 `PackageInstaller` 会话，由系统安装器弹确认；结果沿用 `M2InstallReceiver` 的通知。

## self_create_skill（skill_save 加固）

- 结构校验（`plugins/hoshino-self/skill-check.ts`）：名字 `^[a-z][a-z0-9-]{0,63}$`；描述一行、≤300 字；五个小节 `## 入口 / 步骤 / 容易出错的地方 / 怎样算办成 / 什么时候停下交给用户`（英文 Entry/Steps/Pitfalls/Done when/Hand off 也认）；整份 SKILL.md ≤4000 字；反引号里的名字必须是已注册工具；敏感内容（API key/token、密码验证码、身份证号、卡号、凭据字段）拒绝。
- 内置技能名（不在 `skills/` 目录下的技能，如 `hoshino-self`）不能占用。
- 版本指纹：整份 SKILL.md 的 SHA-256 前 12 位。改已有技能必须带 `version`；`self_read skills/<name>/SKILL.md` 会附带当前 `version`。没带或对不上都拒写。
- 写入用临时文件 + rename，写后读回逐字比对，一致才返回 `{ok:true, action, version}`；否则返回失败、明确「not saved」。
- `self_write` 不能再写 `skills/*/SKILL.md`（避免绕过校验）。
- 准则（`hoshino-tool-protocol` 段，所有模式可见）：`Never invent tool results or claim a create, save or change that no result confirmed.`
