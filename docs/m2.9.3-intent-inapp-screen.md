# m2.9.3：AI 打不开微信（意图门误判）+ 应用内虚拟屏

来源：用户在小米 15S Pro 上装 v0.2.1-m2.9.2（vc215）后的两条真机反馈。版本号不变（随 m2.9.x 发布，本 PR 不发版）。下文根因为**代码推断**，没有拿到出问题那一轮的会话日志，未在真机复现；真机验收清单见文末。

## 一、AI 无法打开微信

### 现象
无审批会话里，模型调用 `phone_launch_app {"app":"微信"}` 立即失败，结果是
`DISCUSS_DENIAL`：「The user is discussing or asking about this, not asking you to act now…」。
这句话来自内核插件 `plugins/hoshino-turn-policy` 的 RT10 意图门（`tools/pre-execute`，prepend，先于审批口子执行），
**请求根本没有到达 Android 侧**，所以与虚拟屏、无线调试助手无关。

### 意图门原来怎么判
1. 每轮第一次调用「非查询类」工具时判一次（`intentDone`），**整轮沿用**这个结论。
2. 判的文本 = 本轮里**最后一条** `source.kind === 'user'` 的消息（`humanText`）。
3. 规则顺序：寒暄 → DISCUSS；含「以后/将来/假如/假设/万一」→ 交给轻模型；含动作词 → ACT；含查询词 → READ；含「什么是/为什么/能不能/建议/如果…」→ DISCUSS；其余 → 轻模型。
4. 轻模型提示词带偏向：「讨论解释说得通、用户又没明确要求时，选 DISCUSS」。
5. DISCUSS = 本轮所有非查询工具一律硬拒，**与审批档无关**（无审批也照拒）。

### 根因结论（代码推断）
对「打开微信」这句话本身，规则判的是 ACT（命中「打开」），不会拒。所以出问题那一轮被判的不是这句话，或者这句话没进规则。按代码能走到 DISCUSS 的路径有四条，本 PR 全部堵上：

| # | 路径 | 例子 |
|---|---|---|
| A | **整轮只判一次**：这一轮由一句提问/寒暄开头（或轻模型判了 DISCUSS），之后在同一轮里插话「打开微信」，结论不重判，照样被拒。插话（dsh `session/prompt mode=steer`）会并入当前轮。 | 「你能操作手机吗？」→ 运行中插话「打开微信」 |
| B | **只看最后一条**：先发「打开微信」，模型第一次调工具前又插了一句「好的/谢谢/嗯」，最后一条是寒暄 → DISCUSS。 | 「打开微信」+「好的」 |
| C | **动作词表太窄 + 轻模型偏向 DISCUSS**：「发个消息」「回复」「进抖音」「去微信…」「用微信给…」都不在动作词表里 → 交给轻模型；提示词让它拿不准就选 DISCUSS，礼貌问句（「你能在微信里…吗」）常被判成讨论。 | 「去微信发个消息」「你能帮我在微信里给妈妈发个消息吗」 |
| D | **条件/将来词一出现就整句交给模型**：明确命令后面跟一个条件从句，也被当成假设。 | 「打开微信，万一有新消息就告诉我」 |

已排除（读代码确认，并有单测覆盖）：接管交还的摘要句随**工具结果**返回，不是用户消息；停止后的交代是 `hoshino-stop-note` 来源；运行时注入、子 Agent 消息、定时任务是别的来源；附件不是文本块，不参与判定。App 断线恢复时发的英文「Resume the interrupted user task…」是用户来源，但规则判 READ，不会拒。

如果方便，导出那次会话（会话菜单 › 导出）就能确认是 A–D 哪一条；从本版起每次意图门的动作都写进 `<selfHome>/audit/intent.jsonl`（只记会话、工具、动作、判定来源，不记用户原话）。

### 修复（`plugins/hoshino-turn-policy`）
1. **无审批会话完全跳过意图门**，子会话沿父会话链继承（复用 m2.9.2 的 `mobileM2.noApproval(sessionId)` → `isNoApproval` → `policyFor` 链式判定）。每轮第一次跳过写一条审计 `skip-no-approval`。
2. **每条人类消息都参与、出现新消息就重判**（新文件 `intent.ts` 的 `humanMessages` / `judgeTurnIntent`）：本轮任一条消息规则判 ACT/READ 即放行；只有最新一条规则判 DISCUSS 才算讨论；都判不了才问轻模型，并把本轮前几条消息作为上下文。修掉 A、B。
3. **DISCUSS 不再硬拒**：默认 `intent.discuss = 'remind'`——第一次被拦的调用返回一次性软提醒（`DISCUSS_REMINDER`：「如果用户明确要你现在做，再调一次就会执行；否则用文字回答」），**同一条用户消息下的下一次被拦工具调用直接放行**。旧的硬拒保留为可选 `'deny'`（`config/context.json`），默认不用。提醒、放行、拒绝都写审计。默认仍然安全：纯讨论题第一次写文件/操作手机仍会被拦一次。
4. **规则补强**：动作词补「发（个/条）消息/微信/红包…」「回复」「点开/点击」「进入/切到」「打电话」「截图」「往下滑」「播放」「去…发/看/找」「用/在/进 + 常见 App + 动作」；条件/将来词只有出现在命令**之前**或整句是问句时才交给模型（修 D，「以后可以帮我同步发布，对吧？」「假如我要发微信，你会怎么做？」仍交给模型）；手机只读工具（`phone_observe/status/list_apps/screenshot/query/extract/wait`）列为查询类，不受门控。
5. **轻模型提示词**去掉「拿不准就 DISCUSS」，改为：现在要做的礼貌请求是 ACT；点名 App/文件/页面的短指令是 ACT/READ；只有明确要解释、意见、计划或谈将来/假设时才是 DISCUSS；中文例句含「打开微信」「去微信给妈妈发个消息」「能不能帮我打开微信」。

### 顺带检查 phone_launch_app
- **中文名解析**：手机上 App 名就是「微信」时旧逻辑能精确匹配，**不是本次原因**；但「WeChat / weixin / 微信app / 打开微信 / 「微信」」以及 ROM 把名字写成「微 信」时都找不到。新增纯函数 `AppNameMatch`：精确包名 → 去掉「打开/App/应用」后精确名（忽略空白、大小写）→ 常用 App 别名（仅当该包已安装，微信 = WeChat = weixin = `com.tencent.mm` 等 22 个）→ 唯一包含匹配；多个候选不猜，错误信息里列出候选。
- **虚拟屏启动路径**：确认走的是特权助手 `PhoneShellService`（内置无线调试助手进程或 Shizuku UserService，均为 shell uid 2000）：`IActivityTaskManager.startActivityAsUser(callingPackage=com.android.shell, ActivityOptions.setLaunchDisplayId(agent))`，失败退到 `am start --display <agent>`，都只针对自己创建的显示。问题：旧代码把返回值 `>= 0` 都当成功，而系统「拒绝启动」的码是正数（100 `START_SWITCHES_CANCELED`、101、102 `START_ABORTED`，ROM 的关联启动/自启动拦截会用它），被拦时模型要等满就绪等待才拿到含糊的「无法确认在前台」。新增 `StartResult`：0–3 才算启动；被拒/出错时用 `am start --display <agent> --user current -n <组件>` 再试一次（同为 shell 身份）；仍被拒返回新码 4，模型看到 `blocked_by_system: …（MIUI/HyperOS 关联启动或自启动拦截）…不要用 system_shell 重试`。**HyperOS 是否真的会拦，未真机验证。**
- 改动的助手代码在 App 更新后要**重连手机助手**（设置 › 设置手机操作）才生效；旧助手进程仍按旧逻辑运行。

## 二、应用内虚拟屏

用户说的「缩放」是指**应用内**看后台屏，不是悬浮球。新增：

### 入口
- 聊天页：手机任务运行或虚拟屏存在时，消息列表上方出现一条「虚拟屏 · 状态 · 当前步骤」栏，带「全屏」「小窗/收起小窗」。
- 独立全屏页「虚拟屏」（路由 `phone/screen`）：侧栏 › 工具 › 虚拟屏；设置 › 权限与系统 › 虚拟屏。
- 无任务时页面显示「启动虚拟屏」（与任务相同的就绪检查：Android 13+、无障碍、助手），启动后可用「打开 App」在虚拟屏里打开任意 App 自己看、自己点。

### 画面与手势（`ui/phone/VirtualScreenSurface.kt`）
- **双指**：捏合无极缩放（1×–8×，以手指为中心）+ 拖动平移；从不注入。
- **双击**：适配 ⇄ 2.5×（以双击点为中心）。开着「双击缩放」时单击要等过双击超时（约 300 ms）才送达；关掉后单击立即送达、双击原样送给 App。
- **单指（操作模式）**：点按 / 长按 / 滑动直接注入虚拟屏；**一碰即接管**、AI 暂停，停手 4 秒自动交还并给 AI 一句摘要；「接管」锁定（不自动交还），「交还」结束。复用悬浮球同一套状态机（`AutoTakeoverModel` + 控制器里的 `ManualTakeover`），新类 `InAppTakeover` 让全屏页和小窗共用一个；接管期间 AI 的每个手机动作都在控制器门口等待（原有逻辑，未改）。页面离开或退到后台时，自动接管立即交还，锁定的接管保留。
- **查看模式**：单指拖动平移放大的画面，不操作手机。
- **输入**：弹出输入框，先在画面里点中输入框再发；可打字的字符逐键发送，中文等经助手借用剪贴板 + Ctrl+V，发完立即还原剪贴板，内容不写日志。另有「返回键」「打开 App」。
- 顶部按钮「复位 n×」一键回到适配。

### 同一变换（显示与触摸一致）
m2.9.2 的 `PreviewTransform` 增加可选的 `zoom: PreviewZoom`：`viewport = zoom.apply(fitViewport)`。GL 中继的视口、Bitmap 绘制矩形、触摸映射都用这个矩形，所以叠加缩放/平移后仍一致。`PreviewZoomTest`：各缩放倍数 × 各焦点 × 平移 × 横竖屏下，所有可见像素「显示 → 视图 → 显示」往返误差 ≤ 1 px；缩放矩形 = 未缩放矩形上再乘同一矩阵（≤ 1.5 px，含一次取整）；捏合时手指下的像素不动；夹紧后画面始终盖满视图、较小的轴居中；单位缩放与 m2.9.2 完全相同。

### 小窗（聊天页画中画，`ui/chat/PhonePip.kt` 重写）
- 标题条拖动移动，右下角「◢」手柄缩放（保持虚拟屏比例，慢拖也连续），「⤢」进全屏页，「×」关闭（聊天栏「小窗」再打开）。
- 位置与宽度按 App 窗口的**竖屏/横屏分别记住**（`phone_pip` prefs）；永远完整留在聊天区内（`PipLayout`，有单测）。
- 小窗里的画面同样可操作、可双指缩放。

### 横竖屏 / 帧率 / 状态
全屏页「画面设置」：竖屏 / 横屏 / 跟随 App（与悬浮球同一个设置）、帧率 5–60（默认 30，同一个设置）、查看模式、双击缩放开关；顶部副标题显示状态与耗时，页面显示当前步骤、最近动作、需要你处理的原因；「停止任务」与悬浮球的停止相同（先交还接管再停）。

### 帧源共用、后台停止
- 零拷贝 GL 中继（`PreviewRelay`）从「只能挂一个预览」改为**可挂多个预览面**，每个有自己的视口（缩放），同一帧 GPU 纹理分别绘制，不重复编码；缩放变化时 `redraw` 用当前帧重画。
- 兼容路径共用 `AgentDisplay.frames`（同一次解码）；全屏页在看时把 Bitmap 预览放大到最宽 1080 px（`hiResWatchers`），小窗和悬浮球仍用 360 px。
- 页面/小窗只在 App 处于前台（`STARTED`）时挂载画面；退到后台卸载 → 停止应用内渲染，回到前台重新挂上。页面/小窗显示期间虚拟屏不会因空闲被回收（`retainViewer`），离开后照旧 5 分钟空闲回收。
- 悬浮球未改：单击 = 控制面板、双击 = 最小化，仍在 Hoshino 前台时隐藏。

## 真机验收清单（小米 15S Pro / HyperOS，均未做）
意图门
1. 默认档新会话说「打开微信」→ 直接打开，无任何拒绝/提醒。
2. 无审批会话说「什么是闭包？然后打开微信」、「你能帮我在微信里给XX发个消息吗」→ 都直接执行；`audit/intent.jsonl` 只有 `skip-no-approval`。
3. 默认档先问「你能操作手机吗？」，运行中插话「打开微信」→ 执行。
4. 默认档问「什么是闭包？」→ 只文字回答，不写文件（模型若坚持会在第二次执行，属预期）。
5. 说「打开 WeChat」「打开微信app」→ 打开微信。
6. 若 HyperOS 拦截后台屏启动：模型收到 `blocked_by_system`，不会反复重试；去系统安全设置放行后可打开。（需先在 设置 › 设置手机操作 重连助手。）

应用内虚拟屏
7. AI 操作手机时聊天页出现「虚拟屏」栏；「全屏」进页面，画面实时、比例正确、无黑边错位。
8. 双指捏合放大到 8×、双指拖动平移、双击切换适配/2.5×、「复位」回到适配；放大后点按位置与画面一致（点按钮命中按钮）。
9. 单指点按/长按/滑动生效；一碰 AI 暂停（状态「你在操作 · AI 已暂停」），停手 4 秒自动交还且 AI 收到摘要；「接管」后不自动交还，「交还」后继续。
10. 「输入」中文进微信输入框；剪贴板内容在发送后还原。
11. 竖屏/横屏/跟随 App 切换、帧率 5/30/60 生效（零拷贝预览开/关两种都试）。
12. 小窗：拖动、右下角缩放、关闭再打开；横竖屏各自记住位置大小；小窗里点按同样生效。
13. 无任务时侧栏 › 工具 › 虚拟屏 → 「启动虚拟屏」→「打开 App」选微信 → 能看能点。
14. 页面打开时按 Home 退到后台：耗电/发热正常（应用内不再渲染），悬浮球照常；回到前台画面恢复。
15. 悬浮球：单击面板、双击最小化不变；悬浮球面板与应用内页面同时存在时（例如分屏）两边都有画面。
