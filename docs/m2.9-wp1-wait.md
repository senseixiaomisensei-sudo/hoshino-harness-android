# m2.9 WP-1：动作后等待与效果判定（A-1）+ 打开 App 等到可用（A-5）

分支 `feat/m2.9-wp1-wait`，基于 `integ/m2.9`（9977220）。不改版本号。

## A-1 动作后等待

**原缺陷**：`AndroidPhoneScreen.waitQuiet` 在动作**之后**才订阅无障碍事件（`PhoneAccessibilityService` 没有订阅者时直接丢事件），
只比“等待开始时”的树哈希。慢页面 400 ms 内没开始变就判安静 → 读回旧页 → `effect=no_effect` → 模型重复点。

**现在**（`StepRunner` → `PhonePort.watch` → `ChangeWait`）：

1. 动作前：取树哈希 + 帧签名（`AgentDisplay.frameSignature()`，12×24 亮度格，原地读、不拷整帧），并以
   `CoroutineStart.UNDISPATCHED` 订阅本屏事件（订阅先于动作建立，动作引起的第一批事件不会丢）。
2. 动作后（无 expect 的步骤）按 `ChangeWait.awaitStableChange` 判定，全部与**动作前**比较：
   - 事件安静 250 ms 且树变了 → 立即返回“变了”（视频、直播画面永远在动也不等）；
   - 只有画面变了（Flutter/游戏/小程序自绘）→ 前后两帧相近才算变了；
   - “没变”要事件安静 + 画面稳定，且只在上限 2.5 s 时下结论 —— 1.2 s、2 s 才开始画的页面也看得到；
   - 到上限时按当时状态下结论（事件不停的页面也不会卡住）。
3. 每步结果多了 `changed`（以及只有画面变时 `frame_only: true`）；`ActionEffects.of(before, after, frameChanged)`
   不再把“只有画面变了”报成 `no_effect`。
4. 带 expect 的步骤：等待事件改为用动作前就建立的订阅计数（先记计数再读屏），读屏和订阅之间到达的事件不再丢；每 750 ms 至少重读一次。

与 Mika 的差别：安静窗口 250 ms（Mika 400）、轮询 100 ms（Mika 150），树哈希只在有事件时重算（或每 400 ms），帧签名不拷整帧。
代价：真正点空的动作要等满 2.5 s 才报 `no_effect`（原来约 0.4 s），这与 Mika 相同，是“慢页面不误判”的必要代价。

## A-5 打开 App 等到真正可用

`open_app` 启动并确认落在代理屏后，按 `LaunchReady` 轮询（100 ms，上限 5 s）：
- 目标包在前台（助手 `topPackage`，问不到时看无障碍顶层窗口），窗口内容也是它自己的；并且
- 可点元素 ≥ 3，或顶层 Activity 相对首次看到时变了（闪屏 → 主页，需要助手的 `topActivity`），或树 1.2 s 不变且至少 1 个可点元素（暖启动回到稀疏页面）；
- 系统选择框（打开方式 / 双开）出现立即返回，让模型选；
- 到上限：仍在前台 → 成功但说明“还没可交互”；确认是别的 App 在前台 → `app_not_in_front` 失败；无法确认 → 成功并提示先读屏。

结果带 `opened_in_ms`。`cold: true`（`phone_launch_app` 与 `phone_do_steps` 的 open_app 都可传）走助手 `restartApp`：
只有该 App 的所有任务都在代理屏上才 `am force-stop` 后重启；在别处有任务（哪怕后台）就改为普通启动并说明；
用户在主屏正用着就不动。旧助手不认识 `restartApp`（返回 0）时退回普通启动并提示重启助手。

AIDL 新增（方法号 41–45 归 WP-1，43–45 预留）：`String topActivity(int displayId) = 41`、`int restartApp(int displayId, String packageName) = 42`
（返回值从不为 0：10=冷启动 11=改为暖启动 1=用户在用 2=无入口 3=失败）。

## 验证

- JVM（本地 JDK17 + kotlinc 单独编译纯逻辑文件已跑通 66 例；完整 Gradle 单测以 CI `verify` 为准）：
  - `ChangeWaitTest`：Mika `ChangeWaitTest` 9 个用例全部移植（“普通翻页”用例的时间窗按 `QUIET_MS` 表达），另加慢页面 600/1200/2000 ms、慢自绘页、动作期间的事件计入安静窗口、静态页快速返回、光标闪烁不算变化。
  - `StepWaitTest`：StepRunner 层用虚拟时间屏幕，旧等待（不覆盖 `watch`）在 600/1200 ms 慢页面上读回旧页且 `no_effect`；新等待读到新页、`done`；50 个 300–1966 ms 的慢页面误判 0 次；静态页 ≤ 550 ms 返回；自绘页按帧判 `done`；点空仍是 `no_effect`；expect 步骤不受影响。
  - `LaunchReadyTest`、`ColdStartTest`（移植）、`PhoneStep` 的 `cold` 解析；node `phone.test.mjs` 增加 `cold` 透传断言。
- 未在真机验证（需要小米 15S Pro）：见 PR 描述的真机验收项。
