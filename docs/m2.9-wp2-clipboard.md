# M2.9 WP-2：剪贴板安全打字

对应 `mika-phone-gap.md` D-5 短期方案 + WP-2。

## 改了什么
- **剪贴板只由助手（shell uid 2000）读写**：新 AIDL `setClipText(16)` / `restoreClip(17)`。App 自己不再读、写或清空剪贴板（原 `paste()` 在后台读到 null 后 `clearPrimaryClip()` 的问题由此消失）。
- **读不到原内容就不碰**：shell 没有 `READ_CLIPBOARD_IN_BACKGROUND` 或读剪贴板 app-op 被关、或读到 null 但系统说「有内容」时，`setClipText` 返回 2（unreadable），剪贴板原样不动；打字改走逐字按键注入 `injectText(18)`（只限可打印、键盘映射得到的字符，全有或全无），再不行报 `needs_ime`。
- **还原**：只在剪贴板仍是我们放的内容（或被系统清空而用户原来有内容）时放回；用户中途复制了别的就不动。助手进程内保存原 clip；App 崩溃没调 `restoreClip` 时 10 s 看门狗自动还原；App 重启连上助手后再补一次 `restoreClip`。
- 我们放进去的 clip 标 `EXTRA_IS_SENSITIVE`（A13+）并抑制「已复制」浮层；还原用户 clip 时只加抑制浮层标记，内容不变。
- 返回码都不为 0：旧助手进程（升级后未重启）对未知事务码回空包，代理读成 0，0 一律当「不支持」，绝不当「已放好」。
- **打字流程（`TypeFlow`，纯逻辑可单测）**：原生输入框 SET_TEXT → 粘贴 → 逐字；WebView 输入框**先判**（祖先是 `android.webkit.WebView`）并先确认焦点（FOCUS → CLICK → 点中心），然后粘贴（`ACTION_PASTE`，失败再 Ctrl+A/V）→ 逐字 → SET_TEXT（报 `set_text_unverified`）；树里看不到的框按屏上文字/树哈希/画面前后比对。每次写入后回读，**都读不回时整条链自动重试一次**；屏有反应但读不出字时停（防重复输入），报 `*_unverified`。
- **按坐标打字 typeAt**：`phone_type_text` / `phone_clear_text` 可只给 x/y（点下没有输入框时）：先点、等稳；点到别的 App 就不打字；出现焦点框则照常输入，否则走看不见的框。
- 错误码：`no_focus`、`point_not_typed`、`needs_ime`、`readback_mismatch`、`not_typed`。
- AIDL 方法号：WP-2 使用 16–18，19–20 预留给 WP-2；WP-5 用 21–30。

## 怎么验的
- JVM 单测：`core-bridge` `ShellClipTest`/`ClipSwapTest`（读不到时零写入、用户 clip 原样放回、中途复制不动、看门狗不误还原、返回码非 0、逐字字符过滤）；`app` `TypeFlowTest`（写入顺序、WebView 先粘贴、回读失败重试一次、needs_ime / point_not_typed / readback_mismatch、读不到原剪贴板时 100 次后台粘贴剪贴板逐字节不变、读得到时 100 次后原样还原）。
- node：`phone.test.mjs` 增加 type/clear 带 x/y 透传。
- CI：verify.yml。
